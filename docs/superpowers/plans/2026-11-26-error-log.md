# Admin Error Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (the user chose **native** execution: one session implements every task, then one whole-branch review). Steps use checkbox (`- [ ]`) syntax for tracking. Do not start coding until the user has approved this plan.

**Goal:** Record every error (API, worker, Next.js server, browser) with exact date/time, page and action into Postgres, a local CSV and a Google Sheet, and show them on an ADMIN-only `/admin/errors` page.

**Architecture:** One `recordError()` in `apps/api/src/features/errors/` is the only write path. It redacts, fingerprints, dedups, then hands one `OutboxRecord` of the new kind `error_log` to the existing `recordLedger()`, which already does DB-or-outbox. After that it appends a row to a daily CSV. The CSV is the local log and the only source for the Google Sheet: a durable sync in the API process reads CSV rows after a saved byte offset and appends them to the Sheet whenever the machine is online, so errors recorded while offline (or before a restart) still reach the Sheet once the internet is back. API, worker and a public ingest endpoint call `recordError`; the web app (browser and Next server) reports through that endpoint.

**Tech Stack:** Express 4, Prisma 6, Postgres, zod, vitest (`apps/api/test/**/*.test.ts`, run `npm test -w apps/api`), Next.js 16.4 / React 19.3, TanStack Query, Playwright (`apps/web/e2e`, API mocked with `page.route`), existing `googleapis` sink.

**Spec:** `docs/superpowers/specs/2026-11-26-error-log-design.md`

## Global Constraints

- One DB row per occurrence; `occurredAt` is timestamptz (UTC). Repeats are grouped by `fingerprint` in queries only. A row may stand for suppressed duplicates through `repeats` (see Task 2). Count = `SUM(repeats)`.
- CSV path `<STORAGE_DIR>/error-logs/errors-YYYY-MM-DD.csv` (UTC day of `occurredAt`), header row once per file, columns include ISO `occurredAt` plus separate UTC `date` and `time`.
- Admin endpoints are ADMIN-only under `adminOnlyRouter`. The client endpoint is `POST /api/v1/client-errors`, rate-limited, body max 8 KB, and works while Postgres is down (no `requireDatabase`).
- Redact tokens, cookies, auth headers, emails, passwords, query strings and IPs. Never store raw IPs or request bodies.
- Sheets copy uses a column allowlist and a redacted stack of at most 500 chars. It stays off unless `SHEETS_SPREADSHEET_ID` and `GOOGLE_SERVICE_ACCOUNT_FILE` are set. Tab name = kind = `error_log`.
- Every CSV row reaches the Sheet eventually (at-least-once): sync state lives on disk (`<STORAGE_DIR>/error-logs/.sheets-sync.json`), survives restarts and offline periods of any length, and is advanced only after Sheets confirms the append. A crash between append and state save can duplicate rows; the `id` column identifies them. Error rows never go through the in-memory mirror queue (that queue drops rows on restart and past 50,000).
- Only the API process runs the Sheets sync; the worker writes CSV rows but never syncs, so rows are not sent twice.
- CSV cells starting with `=`, `+`, `-`, `@`, tab or CR get a `'` prefix.
- Logging must never throw into or change a response. Every hook is wrapped in try/catch, and `recordError` never rejects.
- Record 5xx always. Never record `AppError` 4xx or `ZodError`. Record non-`AppError` 4xx except 400/401/403/404/422 (in practice: Prisma P2002 → 409).
- New modules under `features/errors/` must not import `config/env.js` or `lib/logger.js` statically; use the lazy `log()` pattern from `persistence/outbox.ts` and read `process.env` directly (same reason as there: unit tests must not load the env schema).
- Field caps after redaction: `message` 2000, `stack` 8000, `page` 500, `action` 200, `context` 4000 chars of JSON (else `{ "truncated": true }`), context depth 5.

## Review Focus

- Error storm (same error 1000×/s, or 1000 *different* messages/s): dedup window plus a per-process ceiling must cap writes, and the count must still say how many happened. Tests in Task 2.
- Postgres down while an error occurs: record lands in outbox and CSV, nothing throws, drain inserts exactly once. Task 3.
- Bearer token, JWT, email, `password=` or IP inside a message, page or context: redacted in DB, CSV and Sheet. Task 1 and Task 4.
- PC offline for hours or days (or the API restarted meanwhile), then back online: every CSV row written in that time, across several day files and from both API and worker, appears in the Sheet once, oldest first, with no manual step. Task 4.
- Oversized or garbage body to `/client-errors`: 413 or 422, nothing stored, and the 413 is *not* itself logged as a 500 (today body-parser's `entity.too.large` falls through `normalise()` to 500). Task 5.

## Corrections to the earlier draft (found by reading the code)

1. Global `express.json({ limit: '256kb' })` in `src/index.ts` parses the body before any route-level parser, so a route-level `8kb` limit would never apply. Task 5 skips the global parser for the ingest path.
2. `normalise()` maps body-parser's 413 to a 500, which would turn every oversized report into a recorded 5xx. Task 5 maps `type === 'entity.too.large'` to `AppError.payloadTooLarge`.
3. `csrfGuard` rejects cookie-carrying POSTs without `x-csrf-token`, and `navigator.sendBeacon` cannot set headers. The web reporter uses `fetch(..., { keepalive: true })` with the CSRF header.
4. Validation failures return **422** (ZodError → `AppError.unprocessable`), not 400.
5. `recordLedger()` already does DB and outbox fallback. Reuse it instead of writing a parallel path. Its `enqueueMirror` call is in-memory only (lost on restart, dropped past 50,000 rows, and given up on while offline), so `error_log` records are excluded from it and reach Sheets through the durable CSV sync instead (Task 4). Sheets tabs are keyed by `OutboxKind`, so the tab is `error_log`.
6. A context-key regex of `/ip/i` would drop `description`, `zip`, `recipient`. Use the exact list in Task 1.
7. `GET /export.csv` must be registered before `GET /:id`, or `/:id` swallows it.
8. The web "Export CSV" link must point at `/api/v1/admin/errors/export.csv` (proxied by `next.config.ts` rewrites), not `/admin/errors/export.csv`, which is the Next page.
9. Next 16: `instrumentation.ts` and `instrumentation-client.ts` live in `apps/web/src/` (the app uses a `src` folder); error boundaries receive `{ error, retry }`; `global-error.tsx` renders its own `<html><body>`.
10. Worker permanent failures (`UnrecoverableJobError`) `return` instead of throwing, so BullMQ's `failed` event never fires for them. Hook the catch block, not only the event.
11. `window.reportError` is a browser global; the web function is named `reportClientError` to avoid shadowing it.
12. There is no web unit runner (no vitest in `apps/web`), so web behaviour is tested with Playwright.

Rules the tests pin (implementer writes the bodies):
- `redactText` replaces, in this order: `Bearer <token>` → `Bearer [redacted]`; JWTs `eyJ[\w-]+\.[\w-]+\.[\w-]+` → `[redacted]`; `(password|passwd|pwd|token|secret|api[_-]?key|authorization|cookie|session)\s*[=:]\s*[^\s&,;"']+` → `$1=[redacted]` (case-insensitive); emails → `[redacted-email]`; IPv4 and IPv6 literals → `[redacted-ip]`; any `https?://…?query` → URL without query.
- `redactContext` drops keys matching `/pass|token|secret|cookie|authorization|session|^ip$|^ips$|ipaddress|remoteaddress|x-forwarded-for|^email$/i`; runs `redactText` on every string value; beyond depth 5 replaces with `'[depth]'`; non-plain objects (Error, Date, Buffer) become strings; cycles become `'[circular]'`.
- `normalizeMessage`: UUIDs → `<uuid>`, cuids `\bc[a-z0-9]{24}\b` → `<id>`, hex runs ≥ 8 → `<hex>`, remaining digit runs → `<n>`, whitespace collapsed.
- `topFrame`: first stack line starting with `at ` (trimmed); drop `:line:col`, query strings and `webpack-internal:///`/origin prefixes, so redeploys and chunk hashes don't split a group.
- `fingerprint` = first 16 hex chars of sha256 of `${source}\n${normalizeMessage(message)}\n${topFrame(stack)}`.
- `ERROR_CSV_HEADER` = `['id','occurredAt','date','time','source','severity','status','method','page','action','message','fingerprint','repeats','requestId','userId','context','stack']`. `date` = `YYYY-MM-DD`, `time` = `HH:MM:SS.mmm`, both UTC. `context` is `JSON.stringify`. Null → empty cell.
- `csvEscape`: prefix `'` if first char is one of `= + - @ \t \r`; then quote the cell if it contains `,`, `"`, `\n` or `\r`, doubling inner quotes.
- `appendErrorCsv`: default dir `path.resolve(process.env.STORAGE_DIR ?? './storage', 'error-logs')` (same resolution as `outboxDir()` in `outbox.ts`); `mkdir -p`; create the file with header using `writeFile(file, header + '\n', { flag: 'wx' })` and ignore `EEXIST` (atomic across API and worker processes); then `appendFile(file, row + '\n')`. Rows are one `appendFile` call each (< 64 KB, so one write).

  `id` has no default: `recordError` generates it, so DB row, outbox line and CSV row share one id, and outbox replay is idempotent.
- Outbox record: `{ kind: 'error_log', id, at: occurredAt.toISOString(), data: <ErrorRecord minus id and occurredAt> }`. `parse()` accepts `'error_log'`; `writeToDb` uses `prisma.errorLog.createMany({ skipDuplicates: true, data: [{ id, occurredAt: new Date(rec.at), ...fields }] })`.

`recordError` order: (1) build: redact `message`/`stack`/`page`/`action`, `stripQuery(page)`, `redactContext(context)`, apply caps; (2) fingerprint the redacted message; (3) dedup: `Map<fingerprint, { last: number; suppressed: number }>`. If `now - last < dedupMs`, increment `suppressed` and return. Otherwise write with `repeats = 1 + suppressed`, reset. Prune entries older than `dedupMs` when the map passes 1000 keys; (4) ceiling: sliding count of writes in `windowMs`. Over `max` → drop, keep a dropped counter, log one warn per window (`'Error log ceiling hit; dropped N'`); (5) `await ledger(rec)` in try/catch (on reject, log and still do the CSV); (6) `await csv(rec)` in try/catch. The whole function body sits in an outer try/catch: never rejects, never throws synchronously.

`toErrorInput`: `Error` → `message`, `stack`, plus `cause` chain appended to stack as `\nCaused by: <message>` (max 3 levels); `AggregateError` → first 3 inner messages joined `; `; string → message; other → `JSON.stringify` (fallback `String(err)`); empty message → `'(no message)'`.

- Produces:
```ts
export interface SyncState { files: Record<string, { offset: number }> }   // byte offset of the next unsynced row
export interface ErrorSheetsSyncDeps {
  sink: LedgerSink;
  dir?: string;                               // default <STORAGE_DIR>/error-logs
  isOnline?: () => Promise<boolean>;          // default: dns.promises.lookup('sheets.googleapis.com') within 3 s
  maxRowsPerRun?: number;                     // default 2000
}
/** One pass: oldest file first, rows after the saved offset, in batches of 500. Never rejects. */
export function syncErrorsToSheets(deps: ErrorSheetsSyncDeps): Promise<{ sent: number; pending: boolean; offline: boolean }>;
/** Runs a pass at start, then every intervalMs (default 60_000); after a failed pass, waits with backoff 1, 2, 4 … capped at 15 min. Returns stop(). */
export function startErrorSheetsSync(deps: ErrorSheetsSyncDeps & { intervalMs?: number }): () => void;
/** No-op unless SHEETS_SPREADSHEET_ID and GOOGLE_SERVICE_ACCOUNT_FILE are set. */
export function startErrorSheetsSyncFromEnv(): () => void;
```
- Algorithm for one pass (the implementer writes it; these are the decisions):
  1. If a pass is already running, return (single-flight). If `!(await isOnline())`, return `{ offline: true }` and touch nothing.
  2. Read `.sheets-sync.json` (missing or corrupt → `{ files: {} }`, log warn once). List `errors-*.csv`, sort by name (= by UTC date).
  3. For each file: open it, read from `offset` to EOF, `parseCsvChunk`. If `offset === 0`, drop the header row (and add its bytes to the offset). Map each row to an `OutboxRecord` `{ kind:'error_log', id, at: occurredAt, data }` by header position (`ERROR_CSV_HEADER`), and keep each row's end byte offset.
  4. `sink.write(batch)` per 500 rows. On success, set the offset to the last row's end and **save the state file at once** (write `*.tmp` then `rename`, so a crash never leaves half a JSON file). On `SheetsWriteError`, advance only past the rows not in `remaining`, save, stop the pass. On any other error (network drop mid-pass, 5xx), save what has been confirmed and stop; the next tick retries.
  5. A file shorter than its saved offset (replaced or truncated by hand) → reset that file's offset to 0 and log warn.
  6. Stop after `maxRowsPerRun` rows and report `pending: true`; the next tick continues (a long offline period catches up in bounded chunks rather than one huge request).
- "Connected to the internet" is detected by the DNS check before each pass, and in effect by the append succeeding. No OS network events are needed, so it works the same on Windows and Linux.
